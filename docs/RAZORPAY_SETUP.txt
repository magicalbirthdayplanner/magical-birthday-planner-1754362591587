1. HOW IT WORKS
---------------
  Parent (India party) taps "Choose Starter — ₹…"
   → POST /api/billing/checkout {plan, partyId}            (signed in; party must be theirs; 409 if already owned)
       server: party.country_code = IN → provider Razorpay → price from RAZORPAY_PRICE_STARTER_PAISE
       server: billing_checkouts row (user, party, plan, amount_minor, currency=INR, provider=razorpay)
       server: POST https://api.razorpay.com/v1/orders {amount, currency, receipt=<checkout id>, notes}
       server: stores the order id in billing_checkouts.session_id; returns {checkoutId, keyId, orderId, amount}
   → browser opens checkout.js with that order (key id only — never the secret)
   → Razorpay handler → POST /api/billing/razorpay/verify {checkoutId, razorpay_order_id, payment_id, signature}
       server: checkout must be the caller's own Razorpay checkout (RLS)
       server: HMAC_SHA256(<OUR order id>|payment_id, KEY_SECRET) == signature (constant time)
       server: GET /v1/payments/<id> → must belong to our order; captured → plan; authorized → pending
       server: amount + currency must equal our order exactly, else status 'review' (unlocks nothing)
   → /checkout-success?ref=<checkoutId> polls /api/billing/status (server truth only)
  In parallel: Razorpay → POST /api/webhooks/razorpay (HMAC of the RAW body with WEBHOOK_SECRET, idempotent on
  x-razorpay-event-id) → same recorder. If the browser closes after paying, the webhook alone grants the plan.

Data: billing_checkouts(provider='razorpay', amount_minor, currency, session_id=order id) → billing_purchases
(provider='razorpay', provider_ref=payment id [unique], provider_order_ref=order id, scope='party', party_id).
Entitlement: party_plan(party) / has_paid_access(party) — the same per-party functions Dodo uses.


2. DASHBOARD STEPS (owner)
--------------------------
 1. Create/activate a Razorpay account for the business (KYC, bank account). [NEEDS BUSINESS APPROVAL]
 2. Test mode → Account & Settings → API Keys → Generate Test Key. Note the Key Id (rzp_test_…) and Key Secret.
 3. Test mode → Account & Settings → Webhooks → Add New Webhook:
      URL:     https://magicalbirthdayplanner.app/api/webhooks/razorpay
               (for a preview deployment: that deployment's URL + /api/webhooks/razorpay)
      Secret:  a long random string (this becomes RAZORPAY_WEBHOOK_SECRET)
      Events:  payment.captured, payment.failed, payment.authorized, order.paid, refund.processed
 4. Account & Settings → Payment Capture → Automatic capture (recommended by Razorpay; payments that are never
    captured are auto-refunded and would never unlock a plan).
 5. Keep International Payments OFF at launch (see the pricing proposal).
 6. Optional: Checkout branding (logo/colour) in the dashboard. The app passes name "Magical Birthday Planner".
 7. Repeat 2–3 in LIVE mode only after test mode passed and the go-live checklist below is complete.


3. ENVIRONMENT VARIABLES (names only — never commit values)
-----------------------------------------------------------
  RAZORPAY_ENABLED                 "true" to allow India checkout. Anything else = off (India shows "coming soon").
  RAZORPAY_KEY_ID                  rzp_test_… / rzp_live_…  (sent to the browser by design; mode is read from it)
  RAZORPAY_KEY_SECRET              SECRET. Server only (orders, payment fetch, payment signatures).
  RAZORPAY_WEBHOOK_SECRET          SECRET. Server only (webhook signatures).
  RAZORPAY_LIVE_PAYMENTS_ENABLED   must be "true" in addition when the key is rzp_live_ (two-key rule, like Dodo).
  RAZORPAY_PRICE_STARTER_PAISE     approved price in paise, e.g. 29900 (no defaults: unset = not for sale)
  RAZORPAY_PRICE_PLUS_PAISE
  RAZORPAY_PRICE_PRO_PAISE
  NEXT_PUBLIC_INDIA_ENABLED        "true" shows India in the country pickers and serves /in (build time).
  Test-only (never in Preview/Production): RAZORPAY_API_BASE_URL, NEXT_PUBLIC_RAZORPAY_CHECKOUT_URL.
Set them in Vercel → Project → Settings → Environment Variables, secrets as "Sensitive". Redeploy after changes
(NEXT_PUBLIC_* are build-time).

6. OPERATIONS
-------------
- Unmatched payment (party deleted before payment): unlocks nothing, Sentry PAYMENT_UNRESOLVED; fix with
  select public.reconcile_purchase('<purchase id>', '<party id>');  (service role; same as Dodo).
- Amount/currency mismatch: purchase status 'review' — investigate in Razorpay; refund or grant via admin override.
- Turn India checkout off immediately: set RAZORPAY_ENABLED=false (or unset) and redeploy. Existing purchases keep
  their plans; new India checkouts show "coming soon".
- Telemetry (Sentry): RAZORPAY_VERIFY, RAZORPAY_WEBHOOK(_INVALID_SIGNATURE), RAZORPAY_CHECKOUT_UNAVAILABLE,
  razorpay.webhook.latency; errors fingerprinted razorpay-webhook / razorpay-webhook-config.
- Rotate secrets: create a new key / webhook secret in the dashboard, update Vercel, redeploy. During webhook secret
  rotation, Razorpay retries of older events are signed with the OLD secret — expect a few 401s, then retries succeed
  only if re-sent; reconcile from the dashboard if needed.
