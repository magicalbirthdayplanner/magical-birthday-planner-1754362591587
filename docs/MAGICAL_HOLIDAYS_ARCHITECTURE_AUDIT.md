## 2. Reusable as-is

- **Auth, accounts, roles, Super Admin gate** — parents sign in exactly as today.
- **Billing pipeline**: hosted Dodo checkout, signed webhook verification, idempotency ledger, out-of-order handling,
  refund → revoke, two-switch live mode, `review` hold for under-priced payments, unresolved-payment alerting.
- **Usage-ledger pattern** from `lib/ai/usage.ts` (`ai_reserve` / `ai_finalize`, atomic global breaker) — the model for
  reserving a Santa call before the provider session is created.
- **AI safety helpers** (`sanitizeFreeText`, `wrapParentNotes`) for parent-entered personalisation.
- **Observability** (Sentry with PII scrubbing), first-party analytics with allow-list, Meta Pixel.
- **Design system components**, Nunito typography, BottomSheet, Card, buttons, `StickyCTA`, error/empty states.
- **PWA plumbing** (manifest route, SW, install prompt, offline page) — needs new icons/name only.
- **Admin screen** shell, stats route pattern, audit log.
- **Test harness**: local Supabase integration tests, Playwright mobile projects, mock servers.

## 3. Needs modification

| Item | Change |
|---|---|
| Brand | Introduce `lib/brand/` (name, wordmark, colours, icons, metadata, manifest, email sender name) and read it everywhere the literal brand appears (21 files + layout + manifest + emails + Dodo product names) |
| `next.config.js` Permissions-Policy | Allow `microphone=(self)` and `camera=(self)` (and the avatar provider's origin if its SDK uses an iframe) — on the Santa call route only if possible |
| CSP / connect | Provider WebRTC/WSS origins if a stricter CSP is added later (today only `frame-ancestors` is set) |
| Billing catalogue | Add **Santa packs** (one-time products) next to party plans: product ids, prices, quantity of calls, seconds per call. Today every product maps to a party plan and **a DB trigger rejects any purchase that is not party-scoped** → new purchase scope (`santa`) or a separate credit ledger keyed by the purchase |
| Webhook decision (`lib/billing/events.ts`) | Recognise Santa products and grant call credits instead of a party plan |
| Admin | New Santa operations panel (calls, failures, minutes, provider cost, margin, kill switch) |
| Analytics allow-list | Add the Santa funnel events (no child names) |
| Privacy policy / Terms | Rewrite the children's-privacy section — current text ("we do not knowingly collect personal information from children under 13") is **incompatible** with a product where a child speaks to an AI on camera/mic |
| Service worker | Never cache the call route; bump version for new icons |
| Rate limiter | In-memory per instance is not good enough for paid-session creation → enforce in Postgres (atomic RPC), like `ai_reserve` |

## 4. Must be built (new)

1. **Santa avatar + voice** at the chosen provider (custom replica/avatar, voice, persona).
2. **`SantaAvatarProvider` abstraction** + one concrete provider adapter + a `mock` adapter for tests/E2E.
3. **Santa orchestration**: versioned prompt layers (personality / safety / per-call personalisation), call-time
   context builder, server-side max duration, provider webhook handler (signature verified), usage reconciliation.
4. **Data model** (new migration): child profiles, parental consents (versioned), call credits, calls/sessions
   (status machine, provider ids, connected/ended timestamps, billed seconds, end reason, cost estimate), ops flags
   (kill switch). No transcripts or media by default.
5. **Session API**: `POST /api/santa/calls` (auth → consent → credit reservation → provider session → short-lived
   join credentials), `POST /api/santa/calls/:id/end`, `GET /api/santa/calls/:id`, `POST /api/webhooks/santa/<provider>`,
   plus a reaper (cron) that ends/settles stuck sessions.
6. **Call UI**: full-screen call screen (Santa video, connecting state, timer, mute, end, parent controls, permission
   and autoplay recovery, reconnect, never an endless spinner).
7. **Parent flows**: landing page, package selection, child profile + personalisation, consent, dashboard
   (credits, calls, purchase history, child profiles, deletion request, support).
8. **Santa-hat icon set** and Holidays OG image.
9. **Safety test suite** (prompt red-team cases run against the live persona) and a manual device test matrix.
10. **Docs** listed in the brief.

## 6. Implementation risks

| Risk | Severity | Notes |
|---|---|---|
| **Child-directed product with live voice/video to third-party AI** (COPPA as amended 2025, compliance date 2026-04-22; state laws; provider terms that may forbid use by under-13s) | **Critical / possible launch blocker** | Needs counsel sign-off and provider written confirmation. Engineering can build verifiable-parental-consent-compatible flows (card payment + direct notice), but cannot certify compliance |
| Custom avatar lead time (training/approval, consent video rules for a real actor) | High | Determines Dec 1 feasibility; start immediately |
| Provider concurrency limits during Christmas peaks | High | Needs enterprise/plan upgrade negotiated now; queue/"Santa is busy" UX |
| Unit economics at $2.49 (provider per-minute + Dodo fixed fee ≈ $0.40+) | High | Must be measured before prices are published |
| Rebranding the live birthday product in place would break current customers, SEO, ads and the Pinterest/Meta domain setup | High | See decision D1 |
| Mobile Safari WebRTC autoplay/mic quirks, iOS in-app browsers (Instagram/Facebook webviews where ads land) | Medium–High | Real-device testing; "open in Safari" guidance |
| Serverless has no long-lived process → cannot proxy media; must be browser ↔ provider direct with server-minted tokens and provider-side max duration | Medium | Fine with any of the candidate providers if they support server-set max duration |
| Per-instance rate limiter | Medium | Use DB-atomic reservation for paid sessions |
| No real live Dodo purchase observed yet (`KNOWN_LIMITATIONS.md`) | Medium | Do a real $ purchase in staging/live before launch |
